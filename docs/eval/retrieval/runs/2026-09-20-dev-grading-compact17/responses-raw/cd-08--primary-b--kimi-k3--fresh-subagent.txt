Its doc comment says: "// GenYamlTreeCustom creates yaml structured ref files."

What it does, per the source in the response:

1. Recursion over subcommands: it iterates `for _, c := range cmd.Commands()` and skips any subcommand where `!c.IsAvailableCommand() || c.IsAdditionalHelpTopicCommand()`, then calls itself recursively: `GenYamlTreeCustom(c, dir, filePrepender, linkHandler)`, returning immediately on error. (The supporting definition of `IsAvailableCommand` is included at command.go lines 1559-1576: a command is unavailable if it has a non-empty `Deprecated` string or is `Hidden`, or if it is the parent's help command; otherwise it is available if it is runnable or has available subcommands.)

2. Filename construction: `basename := strings.ReplaceAll(cmd.CommandPath(), " ", "_") + ".yaml"`, then `filename := filepath.Join(dir, basename)` — so each command's full command path, with spaces replaced by underscores, becomes a `.yaml` file in `dir`.

3. File writing: it creates the file with `os.Create(filename)` (returning the error on failure, with `defer f.Close()`), writes `filePrepender(filename)` to the top of the file via `io.WriteString(f, ...)`, and then writes the command's YAML body by calling `GenYamlCustom(cmd, f, linkHandler)`, propagating any error.
