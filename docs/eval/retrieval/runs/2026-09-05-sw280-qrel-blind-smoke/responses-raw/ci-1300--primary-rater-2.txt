In this codebase (cobra), flags are validated after parsing via two Command methods, both gated on c.DisableFlagParsing (return nil if flag parsing is disabled) and both invoked as part of command execution (execute is recorded as a caller of ValidateFlagGroups: "caller: method cobra.Command.execute (command.go:874)"):

1. Command.ValidateRequiredFlags() (command.go:1147, snippet lines 1141-1153): "ValidateRequiredFlags validates all required flags are present and returns an error otherwise." It does `flags := c.Flags()` and builds a `missingFlagNames` slice, i.e. it walks the FlagSet returned by Flags() (command.go:1643, which lazily builds c.flags via flag.NewFlagSet) and reports any required flag that was never set.

2. Command.ValidateFlagGroups() (flag_groups.go:81, snippet lines 75-87): "ValidateFlagGroups validates the mutuallyExclusive/oneRequired/requiredAsGroup logic and returns the first error encountered." It also starts with `flags := c.Flags()` and then delegates to three package-level helpers that each take a `map[string]map[string]bash]bool` of flag name -> isSet built from the flags' annotations:
   - validateOneRequiredFlagGroups (flag_groups.go:167, snippet 161-173/182-194): iterates `sortedKeys(data)`, collects which flags in the group are `isSet`; if none are set, errors "at least one of the flags in the group [%v] is required" (flag_groups.go:183). The snippet just above it (161-164) shows the sibling "required-together" check's error: "if any flags in the group [%v] are set they must all be set; missing %v".
   - validateExclusiveFlagGroups (flag_groups.go:188, snippet 182-194/203-215): same shape, but errors "if any flags in the group [%v] are set none of the others can be; %v were all set" (flag_groups.go:204) when more than one flag in a mutually-exclusive group is set.
   - sortedKeys (flag_groups.go:209) is a shared helper that returns the group names in deterministic (sorted) order for iteration.

To set up which flags get checked this way, you register a group before execution with Command.MarkFlagsRequiredTogether(flagNames...) (flag_groups.go:33, snippet 27-39): it calls `c.mergePersistentFlags()`, then for each name does `f := c.Flags().Lookup(v)`, panicking with "Failed to find flag %q and mark it as being required in a flag group" if the flag doesn't exist, and otherwise marks it with an annotation constant (e.g. `oneRequired`, `mutuallyExclusive` per the const block in the same snippet). Equivalent marking methods exist for the one-required and mutually-exclusive groups (evidence shows constants `oneRequired = "cobra_annotation_one_required"` and `mutuallyExclusive = "cobra_annotation_mutually_exclusive"` at flag_groups.go:27-28).

So the validation flow is: mark flags into named groups via MarkFlags*Together/annotations ahead of time, then when the command executes, Command.execute (command.go:874) triggers ValidateFlagGroups() and ValidateRequiredFlags(), which read the actual "is this flag set" state off the FlagSet from Command.Flags() (command.go:1643) and return one of the group-specific errors above the moment the constraint is violated.
