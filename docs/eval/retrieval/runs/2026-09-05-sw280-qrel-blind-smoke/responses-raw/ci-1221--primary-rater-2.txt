Set the `Version` field on your `cobra.Command` struct — it is a plain Go string field, so you can assign it dynamically at runtime rather than hard-coding a literal (e.g. from a variable populated by build-time ldflags, an env var, etc.).

Evidence:
- site/content/user_guide.md:592 (snippet lines 586-598): "Cobra adds a top-level '--version' flag if the Version field is set on the root command. Running an application with the '--version' flag will print the version to stdout using the version template."
- command_test.go:2571 area (snippet lines 2565-2577) shows the field being set directly on construction: `rootCmd := &Command{Use: "root", Version: "1.0.0", Long: "Long description"}` — the same assignment works with a variable instead of the literal "1.0.0".
- command.go:1204, `InitDefaultVersionFlag` (snippet lines 1198-1210): "If c.Version is empty, it will do nothing." This confirms Cobra checks `c.Version` at execute time, so whatever value you've assigned to it (static or computed) by the time the command runs is what gets used — there's no separate registration step needed beyond setting the field.

If you also want to control how that dynamically-set version string is displayed, use `cmd.SetVersionTemplate(s string)` (command.go:353, doc comment: "SetVersionTemplate sets version template to be used. Application can use it to set custom template."), as referenced again in user_guide.md:592's snippet: "The template can be customized using the cmd.SetVersionTemplate(s string) function."

So concretely: `rootCmd.Version = myDynamicVersionString` (set it any time before `Execute()` runs, e.g. from a package-level var populated via `-ldflags "-X ..."`), and optionally `rootCmd.SetVersionTemplate(...)` to change the output format.
