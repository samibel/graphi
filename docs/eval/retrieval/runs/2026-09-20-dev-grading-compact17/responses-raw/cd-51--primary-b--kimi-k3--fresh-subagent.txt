Append the description text directly to each completion string, separated from the completion value by a tab character (`\t`). According to the returned source span (site/content/completions/_index.md, lines 355-395, "Descriptions for completions"), "Cobra allows you to add descriptions to your own completions. Simply add the description text after each completion, following a `\t` separator. This technique applies to completions returned by `ValidArgs`, `ValidArgsFunction` and `RegisterFlagCompletionFunc()`."

Concrete examples from the documentation:

With ValidArgsFunction:
```go
ValidArgsFunction: func(cmd *cobra.Command, args []string, toComplete string) ([]string, cobra.ShellCompDirective) {
	return []string{"harbor\tAn image registry", "thanos\tLong-term metrics"}, cobra.ShellCompDirectiveNoFileComp
}
```

With ValidArgs:
```go
ValidArgs: []string{"bash\tCompletions for bash", "zsh\tCompletions for zsh"}
```

Additional caveats from the same span:
- Descriptions are supported for each shell, but for bash they are only available in the completion V2 version ("for bash, it is only available in the [completion V2 version](#bash-completion-v2)").
- For commands and flags, Cobra supplies descriptions automatically from usage information; the manual `\t` technique is for your own custom completion values.
- End users can turn descriptions off by passing `--no-descriptions` when generating the completion script, e.g. `source <(helm completion bash --no-descriptions)`, after which completions are listed without descriptions.
