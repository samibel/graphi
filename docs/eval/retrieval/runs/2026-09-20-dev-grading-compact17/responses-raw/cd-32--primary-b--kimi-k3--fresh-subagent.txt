Cobra detects this with the helper `helpOrVersionFlagPresent` in completions.go (lines 521-532). For each of the two flags it performs three checks on the command's full FlagSet:

1. Lookup by name: `cmd.Flags().Lookup("version")` and `cmd.Flags().Lookup("help")` must return a non-nil flag (i.e., the flag actually exists on the command after `mergePersistentFlags` has merged local and all parents' persistent flags into `c.Flags()` — see command.go:1640-1653 and command.go:1846-1853).
2. Cobra-set annotation: the flag must carry the `FlagSetByCobraAnnotation` annotation — `len(versionFlag.Annotations[FlagSetByCobraAnnotation]) > 0` (and likewise for `helpFlag`). This annotation is what marks the flag as one Cobra added itself: `InitDefaultHelpFlag` (command.go:1182-1198) creates the default `help`/`h` bool flag only when `c.Flags().Lookup("help") == nil`, and then stamps it with `_ = c.Flags().SetAnnotation("help", FlagSetByCobraAnnotation, []string{"true"})`. These default flags are initialized "at the last point possible to allow for user overriding" via `c.InitDefaultHelpFlag()` and `c.InitDefaultVersionFlag()` (command.go:883-886).
3. Changed state: the flag's `Changed` field must be true, meaning the user actually supplied it on the command line.

Only if a flag passes all three conditions (exists, was set by Cobra, and was changed by the user) does the function return true, telling the completion logic (per the comment at completions.go:300, "Let's add the --help and --version flag ourselves but only if the finalCmd...") that the flag is already present so it is not added again.
