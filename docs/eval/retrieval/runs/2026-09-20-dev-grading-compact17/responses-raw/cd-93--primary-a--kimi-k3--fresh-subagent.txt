"Post-run" in this codebase refers to the post-run hooks on the `Command` struct in command.go (this is a Cobra-style command library).

**Hook fields (command.go, lines 136-143, also visible in the follow-up read of command.go:47-166):**
- `PostRun func(cmd *Command, args []string)` — "PostRun: run after the Run command."
- `PostRunE func(cmd *Command, args []string) error` — "PostRunE: PostRun but returns an error."
- `PersistentPostRun func(cmd *Command, args []string)` — "PersistentPostRun: children of this command will inherit and execute after PostRun."
- `PersistentPostRunE func(cmd *Command, args []string) error` — "PersistentPostRunE: PersistentPostRun but returns an error."

**Execution order (Command struct doc comment in command.go:47-166):**
"The *Run functions are executed in the following order: PersistentPreRun(), PreRun(), Run(), PostRun(), PersistentPostRun()." So `PostRun` runs immediately after `Run`, and `PersistentPostRun` runs last, after `PostRun`. "All functions get the same args, the arguments after the command name."

**Conditional execution:** "The *PreRun and *PostRun functions will only be executed if the Run function of the current command has been declared" (command.go lines 121-123 and the struct doc comment). So a post-run hook never fires for a command with no `Run`/`RunE`.

**Inheritance:** Per site/content/user_guide.md lines 605-611 ("## PreRun and PostRun Hooks"), "PersistentPostRun and PostRun will be executed after Run. The Persistent*Run functions will be inherited by children if they do not declare their own." The field comments confirm `PersistentPostRun` is inherited by children and executes after `PostRun`, while (by contrast with the explicit "children of this command will not inherit" note on `PreRun`) plain `PostRun` is not inherited.

**Traversal option (cobra.go lines 64-65):** `EnableTraverseRunHooks` "executes persistent pre-run and post-run hooks from all parents. By default this is disabled, which means only the first run hook to be found is executed" — i.e., by default only the nearest parent's persistent post-run hook runs; enabling the flag runs all parents' persistent hooks up the chain.

**Implementation entry point:** There is an internal method `func (c *Command) postRun()` at command.go lines 1020-1021, which presumably dispatches the post-run hooks, but its body is not included in the provided responses, so its exact behavior (e.g., how it selects between PostRun/PostRunE and walks parents) cannot be described.
