Cobra reports a flag parsing error to the user by printing the command's usage message. site/content/user_guide.md, under the heading "## Usage Message" (line 554, snippet span 548-560), states directly: "When the user provides an invalid flag or invalid command, Cobra responds by showing the user the 'usage'." That same snippet shows the usage/help behavior is customizable per-command via `cmd.SetHelpFunc(f func(*Command, []string))` and `cmd.SetHelpTemplate(s string)`, and notes these propagate to child commands.

The response also surfaces a separate, narrower error path that should not be confused with general flag-parsing errors: completions.go defines a `flagCompError` type (completions.go:45, span 44-56) with fields `subCommand` and `flagName`, and an `Error()` method (completions.go:50) that returns the message `"Subcommand '<subCommand>' does not support flag '<flagName>'"`. That type is used specifically during shell-completion flag lookup (referenced from `getCompletions`, completions.go:266, and `checkIfFlagCompletion`, completions.go:592) — it's an internal completion-time error, not the mechanism for reporting an ordinary invalid/unparseable flag on the command line, which is the usage-message behavior described above.

No snippet in the response shows the actual code path that prints usage on a parse failure (e.g. no view of `ExecuteC` in command.go beyond its listing at line 1052/1098, and no snippet content from command.go), so the "usage message on invalid flag" claim rests on the user_guide.md documentation text rather than on a source-code snippet of the parse-error handling itself.
