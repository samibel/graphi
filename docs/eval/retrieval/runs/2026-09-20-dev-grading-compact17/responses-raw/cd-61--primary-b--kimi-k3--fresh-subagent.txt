Usage: getCompletions (completions.go:266-385) has signature

and returns a directive alongside the completion list:
- ShellCompDirectiveDefault — when the real command cannot be found ("Unable to find a command for arguments: %v"), when flag parsing fails ("Error while parsing flags from args %v"), or when a flag-completion error is propagated.
- ShellCompDirectiveNoFileComp — when the --help or --version flag is present ("If they are present, there should be no further completions": return finalCmd, []string{}, ShellCompDirectiveNoFileComp, nil).
- ShellCompDirectiveFilterFileExt — when completing a flag value whose flag has the BashCompFilenameExt annotation with a non-empty extension list ("File completion filtered by extensions": return finalCmd, validExts, ShellCompDirectiveFilterFileExt, nil).
- ShellCompDirectiveFilterDirs — when the flag has the BashCompSubdirsInDir annotation, either with the single subdirectory ("Directory completion from within a directory": return finalCmd, subDir, ShellCompDirectiveFilterDirs, nil) or plain ("Directory completion": return finalCmd, []string{}, ShellCompDirectiveFilterDirs, nil).

The directive is then handed to the generated shell script: bash_completionsV2.go:55-56 shows the generated function "__%[1]s_get_completion_results()" whose comment says it "fills the 'out' and 'directive' vars" — i.e., the completion results and the directive travel together to the shell.

Because it is a bitmap (type int, values from 1 << iota, combined/tested with &), multiple directive behaviors can be OR-ed together in one value, which is what the string() method decodes into names like "ShellCompDirectiveError", "ShellCompDirectiveNoSpace", etc.
