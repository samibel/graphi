## Fetching the artifact (not committed — size)

The tests look in `$GRAPHI_SPIKE_MODEL_DIR` first, then in
`$HOME/.cache/graphi/models/potion-code-16M-v2@e9d2a44ca6a05ac6685f3b23709ea57eb7352d5b/`.
Absent → every artifact-dependent test reports `SKIP: model artifact absent; see PINNED.md`.

```bash
REV=e9d2a44ca6a05ac6685f3b23709ea57eb7352d5b
DIR="$HOME/.cache/graphi/models/potion-code-16M-v2@$REV"
mkdir -p "$DIR"
curl -L https://huggingface.co/minishlab/potion-code-16M-v2/resolve/$REV/config.json      -o "$DIR/config.json"
curl -L https://huggingface.co/minishlab/potion-code-16M-v2/resolve/$REV/tokenizer.json   -o "$DIR/tokenizer.json"
curl -L https://huggingface.co/minishlab/potion-code-16M-v2/resolve/$REV/model.safetensors -o "$DIR/model.safetensors"
curl -L https://huggingface.co/minishlab/potion-code-16M-v2/resolve/$REV/modules.json     -o "$DIR/modules.json"
```

## Oracle fixtures

`testdata/oracle/oracle.json` was generated by `testdata/oracle/gen_oracle.py` with the official
reference implementation:

| `numpy` | 2.5.2 |

| Python | 3.13.5 (darwin/arm64) |

It holds 15 single-text cases (empty, whitespace-only, ASCII identifier, qualified name,
camelCase, snake_case, path segments, Unicode NFC, Unicode NFD, CJK, emoji, a multi-line Go code
block, an NL query, OOV gibberish, a text exceeding the 512-token limit), a batch of 8 mixed

## Epsilon (AC-3)

- Token ids: **exact** (`TestOracle_TokenIDsExact`).
- Vectors: **|Δ| ≤ 1e-5 per component after normalisation** (`oracleEpsilon` in `oracle_test.go`).
  No loosening was needed: the reference-faithful pipeline (`Model.Embed`) reproduces every
  single-text oracle vector **bit-exactly (max |Δ| = 0)**, because it mirrors the reference's
  float16 rounding points (see `embed.go`). The "clean" float32 pipeline
  (`Model.EmbedFloat32`, no float16 rounding after the lookup) sits at max |Δ| = 2.43e-4 — that
  is the cost of NOT mirroring the float16 storage, recorded for SW-262, not a tolerance change.
- Norms: the reference's normalised vectors are float16-valued, so their norms deviate from 1.0
  by up to ~3e-4; the spike reproduces each case's norm to 1e-6 (`TestOracle_NormsReproduced`).

## Reference behaviours mirrored (and the ones deliberately not)

Mirrored, one for one:

1. `BertNormalizer`: clean_text (NUL/U+FFFD/Cc/Cf/Co/Cs/unassigned dropped, all White_Space
   folded to a space), handle_chinese_chars (CJK ideograph blocks padded with spaces),
   strip_accents (defaults to `lowercase` when unset: NFD then drop nonspacing marks), lowercase.
2. `BertPreTokenizer`: whitespace removed, ASCII punctuation and Unicode `P*` isolated.
3. `WordPiece`: greedy longest-match-first, `##` continuation, `max_input_chars_per_word` 100,
   unk `[UNK]` = 1; added tokens `[PAD]` (normalized, single_word, l/rstrip) and `[UNK]`.
4. Right truncation at 512 tokens; no post-processor.
5. Model2Vec `tokenize`: text cut to `512 × median_token_length` (= 7 for this vocabulary)
   **code points** before tokenising, unk ids dropped, then ≤ 512 ids.
6. Pooling in numpy's float16 arithmetic: token-index-ordered float32 sum → ÷ n → round to
   float16; squares rounded to float16; numpy's pairwise sum tree in float32 → float16; sqrt →
   float16; divide → float16. Empty token list → zero vector.

Not mirrored, on purpose — **the batch padding quirk**: `tokenizer.json` declares
`padding: BatchLongest, pad_id 0`, `Tokenizer.encode_batch_fast` applies it, and model2vec strips
only the unk id, so in a batch every text shorter than the longest pools `(longest − own)` copies
of the `[PAD]` row into its mean. The oracle's `batch` block shows it: only the longest text
matches its single-text vector; the others differ by up to **1.95e-3** per component.
`TestOracle_BatchWithinEpsilon` replays the padded arithmetic to within epsilon (the quirk is
understood exactly) and records the distance, but `Model.Embed` is batch-invariant: a node's
vector must not depend on which other nodes share its embedding chunk (determinism decision 4 of
the spec). **SW-262 must decide and document this explicitly** — proposal: batch-invariant, i.e.
the reference's `encode([text])` semantics.

## Documented limits (not covered by the oracle)

- Canonical reordering of combining marks is not performed inside NFD (all nonspacing marks are
  stripped immediately afterwards; only exotic Mc/Me sequences could differ).
- `unicode_categories` (the Rust crate tokenizers uses for `is_control`/`is_punctuation`) carries
  an older Unicode version than Go 1.26's tables; a code point assigned after that version is
  "unassigned" (dropped) for the reference and kept by the spike.
- Rust's `char::to_lowercase` expands U+0130 to two characters; Go maps it to `i`. Irrelevant
  while strip_accents is on (it runs first and removes the dot), so for this artifact.
- The added-token `single_word` boundary is taken as "not letter/digit"; the reference's exact
  word-character predicate is not verified by a fixture. Proposal for a fixture regeneration:
  add cases `"[UNK]"`, `"a [PAD] b"`, `"x[PAD]y"`, `"foo_[PAD]"`, a U+0130, a recent emoji.
